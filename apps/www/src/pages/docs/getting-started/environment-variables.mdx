The API's env file is the source of truth for almost every adapter choice. Start by copying the example:

```bash
cp apps/api/.env.example apps/api/.env
```

Then fill in what you need. Only two variables are *strictly* required to boot the API:

<DocsTable
  columns={["Var", "Required", "Default"]}
  rows={[
    [<code>DATABASE_URL</code>, "yes", "—"],
    [<code>BETTER_AUTH_SECRET</code>, "yes", <code>change-me-in-prod</code>],
  ]}
/>

<DocsCallout kind="warn">
  <code>BETTER_AUTH_SECRET</code> signs every session token. In prod, generate a long random string — <code>openssl rand -hex 32</code> is fine. If you leak or rotate it, every existing session logs out.
</DocsCallout>

## OAuth providers (optional)

better-auth only registers providers whose client id *and* secret are both set. Leave them unset to disable:

- `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET`
- `APPLE_CLIENT_ID` + `APPLE_CLIENT_SECRET`

Redirect URIs to register with each provider: `${API_ORIGIN}/v1/auth/callback/google` and `${API_ORIGIN}/v1/auth/callback/apple`.

## Billing

`BILLING_PROVIDER` is the master switch. When unset or set to `noop`, the billing routes return a disabled-state response and no provider SDK is constructed. Set it to one of `stripe` / `polar` / `dodo` to wire the matching adapter.

### Plan catalog

`BILLING_PLANS_JSON` is a JSON array of plan descriptors rendered on the billing settings page. Keep it small — once you outgrow a handful of plans, replace the env-backed source in `composition.ts` with a DB-backed provider.

```bash
BILLING_PLANS_JSON='[
  {
    "key": "pro",
    "name": "Pro",
    "priceId": "price_...",
    "unitAmount": 800,
    "currency": "usd",
    "interval": "month",
    "intervalCount": 1,
    "features": ["Unlimited teams", "Priority email"]
  }
]'
```

## Uploads (optional)

`UPLOADS_PROVIDER` picks the storage adapter behind `/v1/uploads`. Leave everything unset to disable uploads entirely — the UI hides the avatar upload affordance when it sees the disabled state.

| Variable | Default | Purpose |
|---|---|---|
| `UPLOADS_PROVIDER` | unset | `uploadthing`, `s3`, or `noop`. When unset: `uploadthing` if a token is present, `s3` if the bucket keys are present, otherwise `noop`. `r2` is accepted as an alias for `s3`. |
| `UPLOADTHING_TOKEN` | unset | Token for the hosted adapter. Objects are written private and read through signed URLs. |
| `S3_ENDPOINT` | unset | Endpoint of an S3-compatible store. Cloudflare R2: `https://<account-id>.r2.cloudflarestorage.com`. Omit for AWS S3. |
| `S3_BUCKET` | unset | Bucket name for the `s3` adapter. |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | unset | Credentials with object read/write on the bucket. |
| `S3_REGION` | `auto` | Signing region. R2 accepts `auto`; AWS needs the bucket's region. |
| `S3_KEY_PREFIX` | unset | Optional prefix so several environments can share one bucket. |
| `S3_FORCE_PATH_STYLE` | `false` | Path-style addressing, needed by MinIO and most self-hosted gateways. |

See [Uploads](/docs/integrations/uploads) for the Cloudflare R2 walkthrough.

## Waitlist mode (optional)

- `IS_WAITLIST_ENABLED` — `true` replaces the final step of `/onboarding` with a "you're on the list" screen instead of creating a workspace. `POST /v1/waitlist` accepts submissions regardless.
- `WAITLIST_ADMIN_SECRET` — If set, `POST /v1/waitlist/accept` with `Authorization: Bearer <secret>` marks an entry approved.

## Seed overrides (optional)

The seed script reads a handful of env vars so you can point it at your own email and workspace slug in dev:

- `SEED_OWNER_EMAIL` — default `owner@wereorbit.com`
- `SEED_OWNER_NAME` — default `Demo Owner`
- `SEED_WORKSPACE_SLUG` — default `demo`
- `SEED_WORKSPACE_NAME` — default `Demo`
